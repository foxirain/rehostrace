# Security policy

## Reporting

Do not open a public issue containing an unpatched vulnerability, private capture, credential, link key, proprietary binary, or operational exploit material. Use the repository host's private vulnerability-reporting channel. If that channel is unavailable, open a minimal public issue asking the maintainers to establish a private contact without disclosing technical details.

Include the affected commit, environment, smallest reproducer that can be shared safely, observed consequence, and whether a vendor or upstream project has already been contacted.

## Scope

Reports about parser validation, receipt integrity, unsafe artifact inclusion, schedule/oracle correctness, or unintended information disclosure in this framework are in scope. A seeded public fixture behaving as documented is not a vulnerability.

No target-specific vulnerability material should be added to this repository before coordinated disclosure and a separate publication review.
